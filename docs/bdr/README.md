# Business Decision Records

BDRs capture durable product and business decisions: target users, operating
model, business rules, scope, policy, workflow, autonomy, and commercial
behavior. Use the base status values `Proposed`, `Accepted`, `Deprecated`,
`Superseded`, or `Rejected`.

Naming: `BDR-XXXX-short-title.md`.

A BDR explains why the product behaves this way. Technical implementation
belongs in ADRs. When a later BDR changes an accepted decision, both records
must state the supersession relationship explicitly.
